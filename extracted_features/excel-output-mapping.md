# Excel Output Mapping — Tab-by-Tab Cross-Reference

Maps each tab in the generated Excel workbook to its generating function, data source, columns, accounting invariants, and observations from the sample output. Also documents gaps between code capabilities and what's visible in the 2-PDF demo run.

- **Path:** `output/LBTY_Master_Ledger.xlsx`

## Tab Inventory

### 1. LEDGER_ALL

**Purpose:** Complete flat transaction ledger — all transactions from all ingested statements, post-classification and post-GST-split.

**Generating function:** Direct DataFrame concatenation of per-statement DataFrames after `apply_rules()` + `split_gst_monthly()` + `add_source_txn_id()`

**Columns (13):**

| Column | Type | Description |
|---|---|---|
| Month | str | Statement period (YYYY-MM) |
| SourceAccount | str | Stable account ID (e.g., "BMO_Account27371997_460") |
| SourceAccountLabel | str | Human-readable account label (e.g., "Account #2737 1997-460") |
| InstrumentType | str | "BANK_ASSET" or "CREDIT_CARD_LIABILITY" |
| Date | str | Transaction post date (YYYY-MM-DD) |
| Description | str | Raw transaction description from statement |
| Debit | float | Money out (statement perspective) |
| Credit | float | Money in (statement perspective) |
| Category | str | Classified accounting category (e.g., "Rent", "Income") |
| Confidence | str | Classification confidence tier (Green/Orange/Red) |
| RuleID | str | Which rule classified this transaction (e.g., "LBTY-011") |
| AccountType | str | Accounting type of the counter account (Expense/Income/Liability) |
| SourceTxnID | str | SHA1-based hash ID for audit trail |

**Money columns formatted:** Debit, Credit

**Sample output:** 86 rows × 13 columns (85 transactions + 1 GST split addition across 2 statements)

**Invariants:**
- Every row has a non-empty Category, Confidence, RuleID, and AccountType
- SourceTxnID is unique per transaction (hash-based, not guaranteed unique for identical transactions)

**Features exercised:** F-ING-01, F-ING-02, F-ING-03, F-PAR-01, F-PAR-02, F-PAR-03, F-CLS-01 through F-CLS-07, F-AUD-01

### 2. OPENING_JOURNAL

**Purpose:** Journal entries for manually defined opening balances. Only appears if `opening_balances.csv` has non-zero entries.

**Generating function:** `build_opening_journal_from_csv("opening_balances.csv")`

**Columns (13):**

| Column | Type | Description |
|---|---|---|
| Month | str | "OPENING" (not a real fiscal month) |
| Date | str | "1900-01-01" (sentinel date) |
| SourceTxnID | str | "OPENING-MANUAL" |
| Description | str | "OPENING BALANCES (MANUAL INPUT)" |
| Account | str | Account name from CSV |
| Debit | float | DR amount |
| Credit | float | CR amount |
| AccountType | str | "asset", "liability", or "equity" |
| Confidence | str | "Green" (always) |
| RuleID | str | "OPENING_MANUAL" |
| SourceAccount | str | "OPENING" |
| CounterpartyAccount | str | Offsetting account name |
| Category | str | "Opening Balance" |

**Money columns formatted:** Debit, Credit

**Sample output:** 3 rows (BMO asset opening + Intercompany Clearing liability opening + Opening Balance Offset equity line)

**Invariants:**
- Total Debits = Total Credits within this tab
- If opening balances don't net to zero, an "Opening Balance Offset" equity line absorbs the difference

**Features exercised:** F-ACC-02, F-CFG-01

### 3. TRIAL_BALANCE

**Purpose:** Aggregated account balances from the full journal (opening + activity). Control total for the entire accounting system.

**Generating function:** `build_trial_balance(journal)`

**Columns (4):**

| Column | Type | Description |
|---|---|---|
| Account | str | Account name |
| Debit | float | Sum of all debit entries for this account |
| Credit | float | Sum of all credit entries for this account |
| Net | float | Debit - Credit |

**Money columns formatted:** Debit, Credit, Net

**Sample output:** 20 rows (19 accounts + 1 TOTAL row)

**Invariants:**
- **TOTAL row: Debit = Credit** (fundamental accounting invariant)
- TOTAL Net = 0.00
- Sorted alphabetically by Account

**Features exercised:** F-ACC-04

### 4. JOURNAL

**Purpose:** Complete double-entry journal — every ledger transaction produces two journal lines (debit + credit). Includes opening balance entries.

**Generating function:** `build_journal_from_ledger(ledger)` + `build_opening_journal_from_csv()` concatenated

**Columns (13):**

| Column | Type | Description |
|---|---|---|
| Month | str | Statement period or "OPENING" |
| Date | str | Transaction date |
| SourceTxnID | str | Links back to LEDGER_ALL or opening entries |
| Description | str | Transaction description |
| Account | str | The account being debited or credited |
| Debit | float | DR amount (0.00 if credit line) |
| Credit | float | CR amount (0.00 if debit line) |
| AccountType | str | Asset/Liability/Equity/Income/Expense |
| Confidence | str | Classification confidence |
| RuleID | str | Source rule |
| SourceAccount | str | Control account (bank/card account) |
| CounterpartyAccount | str | The other side of the double entry |
| Category | str | Classified category |

**Money columns formatted:** Debit, Credit

**Sample output:** 173 rows (85 transactions × 2 lines each + 3 opening balance lines)

**Invariants:**
- **Total Debits = Total Credits** (always — this is the double-entry guarantee)
- Every SourceTxnID appears exactly twice (once as debit, once as credit) — except opening entries which may have different structure
- Journal is the foundation for Trial Balance, P&L, Balance Sheet, and all downstream reports

**Features exercised:** F-ACC-01, F-ACC-02

### 5. PL_{year} (one tab per fiscal year)

**Purpose:** Profit & Loss statement for a fiscal year, with monthly columns and a Total column. Shows Revenue, Expenses, and Net Income.

**Generating function:** `build_pl_matrix_from_journal(journal, year)`

**Columns (variable):**

| Column | Type | Description |
|---|---|---|
| Account | str | Category name or section header |
| {YYYY-MM} | float | Monthly amount (one column per month in the fiscal year) |
| Total | float | Row total across all months |

**Money columns formatted:** All columns except Account

**Sample output:**
- **PL_2025:** 9 rows × 3 columns (single month: 2024-12, from CoastCapital LOC)
- **PL_2026:** 19 rows × 3 columns (single month: 2025-10, from BMO)

**Sections:**
1. Revenue header
2. Income account rows
3. Total Revenue row
4. (blank)
5. Expenses header
6. Expense account rows (Auto Insurance, BMO Loan Interest, Bank Fee, Cell Phone, Health Insurance, Office Expense, Payroll, Payroll Remittances, Rent, Royalties)
7. Total Expenses row
8. (blank)
9. Net Income row

**Invariants:**
- Income amounts = Credit - Debit (positive = revenue earned)
- Expense amounts = Debit - Credit (positive = expense incurred)
- Net Income = Total Revenue - Total Expenses
- No Asset/Liability/Equity accounts should appear in P&L
- Fiscal year grouping follows configured start month (default: February)

**Features exercised:** F-RPT-01, F-CFG-02

### 6. BALANCE_SHEET

**Purpose:** Balance Sheet with proper sign conventions and retained earnings roll-forward. No equity plug.

**Generating function:** `build_balance_sheet(tb, journal)`

**Columns (2):**

| Column | Type | Description |
|---|---|---|
| Account | str | Account name or section header |
| Balance | float | Account balance with normal sign convention |

**Money columns formatted:** Balance

**Sample output:** 20 rows

**Sections:**
1. **Assets** header → BMO_Account27371997_460 ($9,407.77) → Total Assets
2. **Liabilities** header → Coast LOC, Credit Card Payable, GST Payable, Intercompany Clearing, Suspense → Total Liabilities ($16,840.28)
3. **Equity** header → Retained Earnings (Opening) (-$43.41) → Current Net Income FY2026 (-$7,389.10) → Retained Earnings (Closing) (-$7,432.51) → Total Equity (-$7,432.51)
4. **Check** row: Assets - Liabilities - Equity = **0.00**

**Invariants:**
- Assets = positive means debit balance (Debit - Credit)
- Liabilities/Equity = positive means credit balance (Credit - Debit)
- Retained Earnings roll-forward: Opening RE + Current NI = Closing RE
- **Check = 0.00** (Assets - Liabilities - Equity)
- NO equity plug — if Check ≠ 0, upstream error exists

**Features exercised:** F-ACC-05

### 7. RECONCILIATION_{year} (one tab per fiscal year)

**Purpose:** Year-level reconciliation proving that extracted transactions match statement balances, plus journal control totals.

**Generating function:** `build_reconciliation(bank_recs, journal, year)`

**Columns (2):**

| Column | Type | Description |
|---|---|---|
| Metric | str | Description of the metric |
| Value | float | Numeric value |

**Money columns formatted:** Value

**Sample output (RECONCILIATION_2026):** 11 rows

**Metrics:**
1. Statement Opening Balance
2. Total Credits Extracted
3. Total Debits Extracted
4. Computed Closing (Opening + Credits - Debits)
5. Statement Closing Balance
6. Diff (Statement - Computed)
7. (blank)
8. Journal Debits
9. Journal Credits
10. Journal Diff (Debits - Credits)

**Invariants:**
- **Diff = 0.00** (extracted transactions reconcile to statement balances)
- **Journal Diff = 0.00** (double-entry integrity)
- Reconciliation formula differs by instrument type (see F-ACC-06)

**Features exercised:** F-ACC-06

## Gaps: Code Capabilities vs. Sample Output

Features present in the codebase but **not fully exercised** or visible in the 2-PDF demo run:

| Gap | What's in Code | What's in Sample | Notes |
|---|---|---|---|
| **Multi-month P&L** | P&L supports monthly columns within a fiscal year | Each P&L tab has only 1 month column | Demo only has 1 statement per fiscal year; with more months, columns would populate |
| **Auto-computed opening balances** | `build_opening_balance_journal()` function exists | Not used — CSV-based approach (`build_opening_journal_from_csv()`) is called instead | Function exists but is not wired into `main()` |
| **Run list mode** | `run_list.csv` support with manual month/opening/closing/payroll columns | Auto-discovery mode used (no `run_list.csv` present) | Both paths exist; demo uses auto-discovery |
| **Multi-client support** | README mentions separating rules into client/statement/firm layers | Single client (LBTY) hardcoded | Future architecture direction only |
| **Exception detection** | Flags accounts with both DR and CR activity | Empty exceptions tab (no exceptions in this run) | Would populate with refunds or misclassification |
| **Multiple months per account** | Reconciliation and P&L designed for multi-month runs | Only 1 month per account in demo | Architecture supports it; demo data is limited |
| **CIBC Bank parser** | `cibc_bank_parser.py` + `cibc_bank_v1.py` exist | Not exercised (no CIBC bank PDF in inputs) | Parser exists and would activate if CIBC PDF added |
| **CIBC Visa parser** | `cibc_visa_parser.py` + `cibc_visa_v1.py` exist | Not exercised (no CIBC Visa PDF in inputs) | Parser exists for credit card instrument type |
| **Payroll subset-sum** | Full combinatorial solver implemented | Exercised (BMO Oct 2025 has payroll_total override) | Working — 4 INTERAC transfers matched to $8,287.66 |
| **Moneris GST split** | Monthly GST allocation with rounding remainder | Exercised (12 Moneris deposits split in BMO Oct 2025) | Working — each deposit split into Income + GST Payable |
| **RUN_SUMMARY TxnCount** | Should show per-statement transaction count | BMO shows TxnCount=0 despite 83 transactions | Possible bug: count uses SourceAccount join but label vs ID mismatch may cause empty join |

## Excel Formatting Details

- **Column auto-fit:** Max width calculated from header + cell content, capped at 50 characters
- **Money formatting:** `numbers.FORMAT_NUMBER_00` (2 decimal places) applied to designated money columns per tab
- **Sheet name limit:** Truncated to 31 characters (Excel limit)
- **Library:** openpyxl (Workbook class, not xlsxwriter)
- **No conditional formatting, colors, or filters** — plain data with number formatting only
